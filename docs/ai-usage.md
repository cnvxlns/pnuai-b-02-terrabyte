# 생성형 AI 활용 내역

## 1. 활용한 AI 도구와 활용 범위

본 프로젝트에서는 요구사항 분석, 설계 검토, 구현, 테스트, 문서화 과정에서 생성형 AI를 개발 보조 도구로 활용했습니다. AI는 반복 작업과 대안 탐색을 지원했으며, 최종 설계·구현·병합 결정은 개발팀이 수행했습니다.

| 도구 | 활용 범위 |
| --- | --- |
| Claude | PM 관점의 요구사항 정리, 기능 단위 작업 분해·배분, 구현 우선순위 및 설계 대안 검토 |
| Codex | 개발자·코드 리뷰어·테스터 역할의 코드 초안 작성, 오류 원인 분석, 리팩터링 제안, 테스트 항목·예외 상황 점검 |
| ChatGPT | 작물 생육 기준, 센서·스마트팜 관련 도메인 자료 조사, 출처 후보 탐색, 문서 초안 작성 |

복합 작업에서는 PM·개발자·코드 리뷰어·테스터 관점을 역할별로 나누어 검토했습니다. 브레인스토밍 단계에서는 복수의 설계안을 제안받고 장단점·예외 상황·구현 비용을 상호 비판한 뒤, 팀 논의를 거쳐 최종안을 결정했습니다. 특히 센서 데이터 처리, 환경 적합도, 관수 추천처럼 사용자에게 영향을 주는 기능은 AI 제안을 참고하되 정책·안전 기준·적용 범위는 팀원이 직접 판단했습니다.

## 2. AI 생성 코드의 검증·수정 방식

1. **요구사항 및 계약 대조**: 생성 코드가 프로젝트 요구사항, 기존 API 계약, 데이터 모델, 센서 통신 형식과 일치하는지 확인했습니다. 기존 코드와 충돌하거나 기능 범위를 벗어나는 제안은 반영하지 않았습니다.
2. **코드 리뷰 및 보완**: 팀원이 입력값 검증, 예외 처리, 인증·권한, 비밀정보 노출, 안전 한계와 오류 시 폴백을 검토하고 프로젝트 구조와 코딩 규칙에 맞게 수정했습니다.
3. **실행·테스트 검증**: 프론트엔드·백엔드·AI 서버·엣지 구성요소를 실제 실행하고, 정상·오류 입력 및 API 연동 시나리오에서 결과를 확인했습니다. 자동 테스트, 타입 검사, 빌드 결과를 함께 검토했습니다.
4. **결과 재검토**: 센서값, 작물별 기준, 적합도 및 관수 추천 결과가 재현 가능하고 상식적인지 확인했습니다. 특정 항목이 누락되거나 비정상 값이 들어오는 상황, AI 서버를 사용할 수 없는 상황도 확인했습니다.
5. **수정 후 재검증**: 불일치·보안 위험·성능 문제가 발견되면 AI 제안을 그대로 사용하지 않고 직접 수정한 뒤 동일 시나리오를 재시험했습니다.

도메인 자료 조사 결과는 원문 출처를 직접 확인한 뒤 문서에 표기했습니다. <br>민감정보는 AI 도구에 입력하지 않았으며, AI 생성 결과는 팀의 검토·수정·검증을 거친 뒤에만 저장소에 반영했습니다.
