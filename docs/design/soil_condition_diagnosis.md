# 토양 환경 유형 판정 (NORMAL / WET_RISK / DRY_RISK)

## 1. 왜 만들었나

`/api/pots/{potId}/soil-recommendation` 은 `target_condition` 을 응답에 담고 있었지만, 서비스가
언제나 `catalog.findNormalProfile()` 만 불렀다. 즉 **모든 화분이 항상 `NORMAL`** 이었고, 배합
추천도 늘 기본형 하나였다. 데이터셋이 작물마다 `WET_RISK` / `DRY_RISK` 프로필을 갖고 있는데도
쓰이지 않았다.

앱 대시보드의 "환경 상태" 표는 이 공백 때문에 토양 행의 범위 칸에 `센서 유효 범위 0~100%` 를
띄우고 있었다. 그 숫자는 `edge/pi/terrabyte_edge/protocol.py` 의 **프로토콜 파싱 검증 경계**로,
사용자에게는 정보량이 0 이다.

## 2. 판정 규칙의 출처

원본은 `backend/src/main/resources/soil/indoor_potting_substrate_recommendations.json` 의
`agent_decision_policy` 와 각 작물의 `diagnosis` 다. 8개 작물의 서술 형식은 제각각이지만 규칙의
내용은 동일하다.

| 유형 | 조건 |
|---|---|
| `NORMAL` | 관수 후 수분이 상승하고 이후 점진적으로 감소, 배수 정상 |
| `WET_RISK` | 높은 수분이 오래 유지되고 감소가 느리며 배수도 느림 |
| `DRY_RISK` | 관수 후 수분이 지나치게 빠르게 감소 |

## 3. 구현이 이 모양인 이유 — hard rules

`agent_decision_policy.hard_rules` 가 구현 형태를 강제한다.

| 규칙 | 구현에 미친 영향 |
|---|---|
| "한 번의 센서값만으로 확정하지 않는다" | 단일 측정으로는 판정하지 않고 `conditionDiagnosed=false` |
| "모든 화분에 공통인 고정 토양수분 퍼센트를 사용하지 않는다" | **절대 임계값이 코드에 하나도 없다.** 모든 판단이 같은 화분의 이전 건조 구간 대비 비율 |
| "동일 화분·동일 센서에서 관수 전후 변화 추세를 우선한다" | 비교 단위가 개별 측정값이 아니라 관수 사이의 '건조 구간' |
| "온도·습도·조도만으로 환경 유형을 확정하지 않는다" | 보조 신호는 단독 판정 불가. 수분 추세가 먼저 움직여야 하고, 보조 신호는 뒷받침만 한다 |

## 4. 알고리즘

1. `soilSensorValid` 인 측정만 시간순으로 추린다. (프로브 없는 노드의 `0.0` 이 '급격한 건조'로
   읽히는 것을 막는다.)
2. 측정 간 변화폭의 **중앙값**을 구하고, 그 `IRRIGATION_RISE_FACTOR`(3.0)배 이상 상승한 지점을
   관수로 본다.
3. 관수를 경계로 건조 구간을 자르고, 구간마다 시간당 감소율(%/h)을 낸다.
4. 구간이 2개 미만이면 판정하지 않는다.
5. 이전 구간들의 감소율 중앙값을 기준선으로 삼는다. 기준선이 0 이하면(정체·상승) 비율 비교가
   성립하지 않으므로 판정하지 않는다.
6. 현재 구간이 기준선의 `FASTER_THAN_BEFORE`(1.5)배 이상이고 공기가 **더 덥고·더 건조하고·더
   밝아졌으면** `DRY_RISK`.
7. 현재 구간이 기준선의 `SLOWER_THAN_BEFORE`(0.6)배 이하이고 공기가 **더 습하고·더 어두워졌으면**
   `WET_RISK`.
8. 그 외에는 `NORMAL`.

조회 구간은 7일(`DIAGNOSIS_WINDOW`). 엣지의 최소 관수 간격이 6시간이라 두 번의 관수가 들어올
여유가 있다.

## 5. ⚠️ 임계값의 근거 수준

`3.0` / `1.5` / `0.6` 은 **실측으로 보정한 값이 아니다.** 데이터셋은 "빠르다 / 느리다"를 서술로만
정의하고 숫자를 주지 않는다. 세 값은 다음 성질만 만족하도록 고른 초기값이다.

- 관수(수십 %p 도약)와 측정 노이즈(1%p 안팎)를 가르는 데 3배면 충분히 여유롭다.
- 1.5배 / 0.6배는 서로 겹치지 않으면서, 한 구간이 다른 구간의 2배 가까이 차이 날 때만 반응한다.

관수 이벤트가 충분히 쌓이면 실제 구간별 감소율 분포를 보고 재보정해야 한다.
`docs/design/irrigation_volume.md` §4.2 가 요구하는 것과 같은 종류의 후속 작업이다.

## 6. 남은 갭

| ID | 내용 | 해소 조건 |
|---|---|---|
| S1 | **배수 상태를 관측할 수 없다.** 규칙 원문은 `WET_RISK` 에 "실제 배수가 느림"을 요구하지만 배수 센서가 없다. 없는 신호를 참으로 가정하지 않고 관측 가능한 두 신호로만 판정한 뒤, 응답의 `pre_checks`(배수구 막힘·받침 물·과대 화분)로 사용자에게 확인을 넘긴다 | 배수 감지 수단 확보 후 |
| S2 | 임계값이 실측 보정 전이다 (§5) | 관수 이벤트 축적 후 |
| S3 | `crop_score_profile` 에 **작물별 목표 토양수분이 여전히 없다.** 이 문서의 판정은 작물 무관 상대 비교라 그 갭을 메우지 않는다. `ml_irrigation_contract.md` G3 는 그대로 열려 있다 | 미정 |

## 7. 화면에 어떻게 나오나

- 판정됨 → `정상` / `과습 주의` / `건조 주의`
- 이력 부족 → `관수 이력 쌓는 중`
- 응답 없음 → `판정 대기`

**토양 온도 행은 `작물별 기준 없음` 으로 둔다.** 이 판정은 배지 수분에 관한 것이라 토양 온도
행에 같은 라벨을 붙이면 근거 없는 진단이 된다. 작물별 토양 온도 기준은 어디에도 없다 —
AI 서버에도 뿌리 활성 곡선에 쓰이는 작물 무관 상수 22℃ 하나뿐이다.
