# 기기 모델 및 텔레메트리 계약 설계

작성일: 2026-08-04 (Asia/Seoul)
상태: **확정** — 이 문서가 계정·기기·화분 구조와 하드웨어↔백엔드 계약의 source of truth다.
관련: [todolist.md](../todolist.md), [HANDOFF.md](../../HANDOFF.md)

## 1. 배경

2026-08-04 코드 감사에서 두 가지 구조적 문제가 확인됐다.

**첫째, 하드웨어→백엔드 경로가 연결되지 않는다.** Orange Pi(`edge/pi`)와 Spring이 서로 다른 계약을
구현하고 있어, 현재 저장소 코드로는 텔레메트리가 단 한 건도 도착할 수 없다.

| | Orange Pi가 보내는 것 | Spring이 받는 것 |
|---|---|---|
| 경로 | `POST /api/crop-contexts/{contextId}/environment-observations` | `POST /api/telemetry` |
| 인증 | `Authorization: Bearer <device token>` | `X-Device-Key` 헤더 |
| 성공 코드 | `201` 기대 | `202` 반환 |
| 본문 | camelCase 5필드 | snake_case envelope |
| 습도 필드 | `relativeHumidityPct` | `air_humidity_pct` |
| 광량 필드 | `ppfdUmolM2S` | `plant_light_ppfd_umol_m2_s` |
| 토양수분 | 전송 안 함 | `soil_moisture_pct` + `soil_moisture_raw_adc` 필수 |

**둘째, 계정·기기 모델이 1:1:1로 고정되어 있다.**

```sql
device:            uq_device_user_id UNIQUE (user_id)
cultivation_space: uq_cultivation_space_user_id UNIQUE (user_id)
                   uq_cultivation_space_device_id UNIQUE (device_id)
device.crop_code   -- 작물이 게이트웨이에 붙어 있음
```

| # | 문제 | 결과 |
|---|---|---|
| 1 | `device.user_id` UNIQUE | 계정당 기기 1대. 화분 2개면 계정 2개 필요 |
| 2 | `cultivation_space` 양쪽 UNIQUE | 공간 1개. "옥상"과 "지하실"을 비교할 수 없음 — 공간 진단 서비스의 핵심 가치 훼손 |
| 3 | 작물이 `device`에 붙음 | 게이트웨이 하나에 화분 여러 개면 작물을 따로 정할 수 없음 |
| 4 | 공용 `X-Device-Key` 하나 (`MeasurementService.authenticateDevice`) | `hardware_id`만 알면 누구나 위조 가능. 기기별 폐기·회전 불가 |
| 5 | `serial_code`가 곧 등록코드이며 영구·불변 | 등록 해제 후 코드를 아는 사람이 탈취 가능. 재발급 불가 |
| 6 | InfluxDB가 `hardware_device_id` 태그로 시계열 저장 | Orange Pi 교체 시 측정 이력 단절 |
| 7 | 기기 프로비저닝이 Flyway `INSERT` (V2, V4) | 기기 추가마다 마이그레이션 필요 |

6번이 시급하다. Influx 시계열의 태그 키를 지금 정하지 않고 나중에 바꾸면, 그 시점까지 쌓인
데이터가 전부 고아가 된다. 지금이 가장 싼 시점이다.

## 2. 확정된 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | **화분(`pot`) 계층을 지금 도입한다** | 지금은 테이블 하나 + FK. Influx에 데이터가 쌓인 뒤에는 태그 마이그레이션 + API 경로 + 프론트가 전부 딸려온다 |
| 2 | **`device` 테이블명을 유지하고 의미만 "게이트웨이"로 확정한다** | `gateway`로 개명하면 Java 6개 클래스·패키지·테스트 3종·프론트 클라이언트가 전부 딸려오는데 얻는 것이 이름뿐이다 |
| 3 | **`POST /api/telemetry`를 유지한다** | envelope v2를 받는 디버그·폴백 경로. curl 한 줄로 전체 파이프라인을 검증할 수 있어 데모 리허설에서 값어치를 한다 |

## 3. 목표 모델 — 4계층

```
app_user
 └─ cultivation_space   공간 (옥상 / 지하실 / 방)        [1:N]
     └─ device          Orange Pi 게이트웨이            [1:N]  ← 인증·MQTT 주체
         └─ pot         Arduino 노드 = 화분             [1:N]  ← 센서·액추에이터·작물·점수 주체
```

설계의 핵심은 **"인증하는 것"과 "작물을 기르는 것"의 분리**다. 현재는 `device` 하나가
등록코드·MQTT 신원·작물·상태를 전부 겸하고 있어서 어느 하나만 바꿔도 나머지가 딸려온다.

이 분리는 억지 확장이 아니다. `edge/pi`가 이미 `X-Device-ID`(게이트웨이)와
`X-Arduino-Node-ID`(노드)를 **별도 헤더로 분리해 전송**하고 있다. 백엔드에만 이 구분이 없다.

### 3.1 각 계층의 책임

| 계층 | 책임 | 책임이 아닌 것 |
|---|---|---|
| `cultivation_space` | 공간 이름·유형·면적. 공간 단위 비교/진단 | 센서, 작물 |
| `device` | MQTT 자격증명, 온라인 상태, 등록코드 claim, 명령 중계 | 작물, 측정값 소유 |
| `pot` | 작물 선택, 측정 시계열의 주체, 적합도 점수, 액추에이터 | 인증 |

## 4. 스키마 변경

기존 마이그레이션은 `V6`까지 존재한다. 아래 4개를 순서대로 추가한다.

### V7__relax_device_ownership.sql

```sql
-- 계정당 기기 1대 제약 해제
ALTER TABLE device DROP CONSTRAINT uq_device_user_id;

-- 공간 소속 (방향 반전: space가 device를 가리키던 것을 뒤집는다)
ALTER TABLE device ADD COLUMN space_id BIGINT;
ALTER TABLE device ADD CONSTRAINT fk_device_space
    FOREIGN KEY (space_id) REFERENCES cultivation_space (id) ON DELETE SET NULL;

-- 등록코드를 serial_code에서 분리 (재발급·회전 가능)
ALTER TABLE device ADD COLUMN claim_code VARCHAR(6);
ALTER TABLE device ADD COLUMN claimed_at TIMESTAMP WITH TIME ZONE;
CREATE UNIQUE INDEX uq_device_claim_code ON device (claim_code);
UPDATE device SET claim_code = serial_code;
ALTER TABLE device ADD CONSTRAINT ck_device_claim_code_length
    CHECK (claim_code IS NULL OR CHAR_LENGTH(claim_code) = 6);

-- 기기별 MQTT 자격증명
ALTER TABLE device ADD COLUMN mqtt_username VARCHAR(100);
ALTER TABLE device ADD COLUMN mqtt_password_hash VARCHAR(255);
ALTER TABLE device ADD COLUMN credential_revoked_at TIMESTAMP WITH TIME ZONE;
CREATE UNIQUE INDEX uq_device_mqtt_username ON device (mqtt_username);
UPDATE device SET mqtt_username = 'gw-' || hardware_id WHERE hardware_id IS NOT NULL;

-- 기존 user_id는 claim된 상태이므로 claimed_at 백필
UPDATE device SET claimed_at = created_at WHERE user_id IS NOT NULL;
```

`serial_code`는 하드웨어 각인 일련번호로 남기고, 사용자가 앱에 입력하는 값은 `claim_code`로 바뀐다.
등록 해제 시 `claim_code`를 재발급하면 이전 코드로는 다시 claim할 수 없다.

### V8__create_pot.sql

```sql
CREATE TABLE pot (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    device_id BIGINT NOT NULL,
    node_id VARCHAR(64),                       -- NULL 허용: 첫 텔레메트리 수신 시 자동 바인딩
    label VARCHAR(100) NOT NULL,
    crop_code VARCHAR(50),
    crop_selected_at TIMESTAMP WITH TIME ZONE,
    status VARCHAR(10) NOT NULL DEFAULT 'OFFLINE',
    last_seen_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_pot_device FOREIGN KEY (device_id) REFERENCES device (id) ON DELETE CASCADE,
    CONSTRAINT fk_pot_crop FOREIGN KEY (crop_code) REFERENCES crop (code),
    CONSTRAINT ck_pot_status CHECK (status IN ('ONLINE', 'OFFLINE')),
    CONSTRAINT ck_pot_crop_selection
        CHECK ((crop_code IS NULL AND crop_selected_at IS NULL)
            OR (crop_code IS NOT NULL AND crop_selected_at IS NOT NULL))
);

CREATE UNIQUE INDEX uq_pot_device_node ON pot (device_id, node_id) WHERE node_id IS NOT NULL;

-- 기존 device마다 화분 1개 생성하고 작물 이관
INSERT INTO pot (device_id, label, crop_code, crop_selected_at, status, last_seen_at)
SELECT id, '화분 1', crop_code, crop_selected_at, status, last_seen_at FROM device;
```

### V9__drop_device_crop.sql

```sql
ALTER TABLE device DROP CONSTRAINT ck_device_crop_selection;
ALTER TABLE device DROP CONSTRAINT fk_device_crop;
ALTER TABLE device DROP COLUMN crop_selected_at;
ALTER TABLE device DROP COLUMN crop_code;
```

### V10__relax_cultivation_space.sql

```sql
-- device.space_id 백필 후 방향 반전 완료
UPDATE device d SET space_id = s.id
FROM cultivation_space s WHERE s.device_id = d.id;

ALTER TABLE cultivation_space DROP CONSTRAINT uq_cultivation_space_user_id;
ALTER TABLE cultivation_space DROP CONSTRAINT uq_cultivation_space_device_id;
ALTER TABLE cultivation_space DROP CONSTRAINT fk_cultivation_space_device;
ALTER TABLE cultivation_space DROP COLUMN device_id;
```

### 4.1 노드 자동 바인딩

`pot.node_id`를 NULL 허용으로 두는 이유는, 기기 등록 시점에는 Arduino의 `TB_NODE_ID`를 알 수 없기
때문이다. 다음 규칙으로 자동 해소한다.

1. 기기 등록 시 `pot` 1개를 `node_id = NULL`, `label = '화분 1'`로 자동 생성한다.
2. 텔레메트리가 도착하면 해당 `device`의 `node_id IS NULL`인 화분 중 가장 오래된 것에
   수신된 `node_id`를 바인딩한다.
3. 미바인딩 화분이 없는데 새 `node_id`가 오면 `pot`을 자동 추가 생성한다
   (`label = '화분 N'`).

사용자에게는 지금과 동일하게 "6자리 코드 입력 → 공간 정보 → 작물 선택"으로 보이고, 다계층 구조는
UI 뒤에 숨는다.

## 5. InfluxDB 태그 변경

```
현재:  telemetry_sample,hardware_device_id=orangepi-pro-01,site_id=...,zone_id=...
변경:  telemetry_sample,pot_id=42,device_id=7,node_id=terrabyte-node-01,crop_code=basil
```

`pot_id`가 **주 조회 키**다. Arduino를 교체해도 `node_id`만 재매핑하면 이력이 이어진다.
하드웨어 식별자를 시계열 태그로 쓰면 안 되는 이유다.

- `InfluxMeasurementStore.write` — 태그를 `pot_id`, `device_id`, `node_id`로 교체
- `findLatest(String hardwareDeviceId)` → `findLatest(long potId)`
- `findPoints(String hardwareDeviceId, ...)` → `findPoints(long potId, ...)`
- 기존 `site_id`, `zone_id`, `soil_type`, `calibration_version`은 컨텍스트 필드로 강등하거나
  유지 — 카디널리티가 낮으므로 태그 유지해도 무방

기존 개발용 Influx 데이터는 마이그레이션하지 않는다. 버킷을 비우고 다시 수집한다.

## 6. 텔레메트리 계약 v2

### 6.1 전송과 페이로드 분리

Orange Pi와 Spring의 계약이 어긋난 근본 원인은 **양쪽이 각자 전송 방식에 페이로드를 묶어놨기**
때문이다. 한 번만 분리하면 MQTT 전환과 curl 디버깅이 같은 코드로 처리된다.

```
계약 v2 (전송 무관)          ┌─ MQTT 구독자              (운영 경로)
  TelemetryEnvelope    ──────┤
                             └─ POST /api/telemetry     (디버그·폴백, 동일 DTO)
```

엣지도 동일하다. `service.py`가 이미 `.send(Event) -> DeliveryResult`만 사용하므로
`Publisher` 프로토콜 하나를 뽑으면 `MqttPublisher` / `HttpPublisher` 교체가 된다.
SQLite outbox는 손대지 않는다.

### 6.2 Envelope

게이트웨이 1건 안에 노드 N건을 담는다.

```json
{
  "schema_version": 2,
  "event_type": "telemetry.sample",
  "gateway_id": "orangepi-pro-01",
  "event_id": "3f2b9c0e-...",
  "observed_at": "2026-08-04T10:00:00Z",
  "nodes": [
    {
      "node_id": "terrabyte-node-01",
      "sequence": 1042,
      "measurements": {
        "air_temperature_c": 27.1,
        "air_humidity_pct": 58.0,
        "plant_light_ppfd_umol_m2_s": null,
        "soil_temperature_c": 21.4,
        "soil_moisture_pct": 31.2,
        "soil_moisture_raw_adc": 1847
      },
      "quality": {
        "air_sensor_valid": true,
        "light_sensor_valid": false,
        "soil_sensor_valid": true
      }
    }
  ]
}
```

**필드명 규칙: 백엔드 `MeasurementMetric` enum 값과 글자 그대로 일치시킨다.**
현재 불일치 6건이 전부 이 규칙 부재에서 나왔다.

| 필드 | 필수 | 비고 |
|---|---|---|
| `air_temperature_c` | ✅ | −50 ~ 80 |
| `air_humidity_pct` | ✅ | 0 ~ 100 |
| `plant_light_ppfd_umol_m2_s` | 선택(nullable) | 값이 있으면 0 ~ 5000 |
| `soil_temperature_c` | 선택 | 신규 metric. −20 ~ 80 |
| `soil_moisture_pct` | 선택 | 0 ~ 100 |
| `soil_moisture_raw_adc` | 선택 | **기존 필수에서 선택으로 완화** |

`soil_moisture_raw_adc`를 필수에서 뺀 이유는, Arduino가 raw ADC를 emit하지 않는데 Spring이 필수로
요구해 계약이 깨져 있었기 때문이다. 보정 검증용으로 유용하므로 필드는 유지하되 선택으로 둔다.

광량 센서가 없거나 고장 난 경우 `plant_light_ppfd_umol_m2_s`는 생략하지 않고 명시적 `null`,
`light_sensor_valid`는 `false`로 보낸다. 이 샘플의 다른 유효 측정값은 정상 저장하지만 환경 적합도는
계산하지 않는다. PPFD 숫자와 `light_sensor_valid=false`, 또는 PPFD `null`과
`light_sensor_valid=true`처럼 서로 모순된 조합은 수집 단계에서 거부한다.

`event_id`는 Orange Pi outbox의 UUID를 그대로 쓴다. 백엔드는 이 값으로 중복 수집을 차단한다.

### 6.3 MQTT 토픽

```
tb/v2/{gatewayId}/up/telemetry     게이트웨이 → 서버   QoS 1
tb/v2/{gatewayId}/up/status        온라인/액추에이터 상태 (LWT 등록)  QoS 1, retain
tb/v2/{gatewayId}/up/ack           명령 응답            QoS 1
tb/v2/{gatewayId}/dn/command       서버 → 게이트웨이     QoS 1
```

`up` / `dn` 분리가 ACL을 한 줄로 만든다.

### 6.4 인증 — Mosquitto가 담당한다

```
# mosquitto acl_file
user gw-orangepi-pro-01
topic write  tb/v2/orangepi-pro-01/up/#
topic read   tb/v2/orangepi-pro-01/dn/#
```

**인증 주체를 백엔드에서 Mosquitto로 옮기는 것이 핵심이다.** ACL이 토픽 위조를 막으므로 백엔드는
토픽에 담긴 `gatewayId`를 신뢰해도 된다. 공용 `X-Device-Key` 검증 로직
(`MeasurementService.authenticateDevice`)이 통째로 사라진다.

데모까지 4주 남은 상황에서는 **자격증명을 미리 10개 발급해 compose 시점에 Mosquitto 패스워드
파일에 넣고, bcrypt 해시를 `device.mqtt_password_hash`에도 저장**하는 방식을 쓴다. 동적 발급
(`dynamic-security` 플러그인)은 데모 후로 미룬다.

`POST /api/telemetry` 디버그 경로는 인증 방식이 다르므로 별도로 다룬다 — §6.6 참조.

### 6.5 LWT로 오프라인 판정

게이트웨이가 접속 시 `tb/v2/{gatewayId}/up/status`에 `{"online": false}`를 LWT로 등록하고,
접속 직후 `{"online": true}`를 retain 발행한다. 연결이 끊기면 브로커가 대신 LWT를 발행한다.

결과적으로 `GET /api/devices/{id}/status`를 위한 별도 폴링 스케줄러가 필요 없어진다
(todolist P1-6의 상당 부분이 사라진다).

### 6.6 HTTP 디버그 경로

`POST /api/telemetry`는 envelope v2만 수용한다. `schema_version`이 2가 아니면 `400`을 반환한다.
v1 하위호환은 제공하지 않는다 — 엣지와 Arduino를 어차피 전부 교체하기 때문이다.

인증은 기존 `X-Device-Key`를 유지하되, **개발 프로필에서만 활성화**한다
(`app.telemetry.http-ingest.enabled`, 기본 `false`, 운영은 비활성).

### 7.2 기존 엔드포인트 — deprecated 별칭으로 유지

작물·측정·점수의 주체가 `device` → `pot`으로 옮겨가므로 경로가 바뀐다. 다만 **기존 device 스코프
경로는 "해당 기기의 대표 화분"(가장 낮은 `pot.id`)으로 위임하는 별칭으로 남긴다.**

| 기존 (deprecated) | 위임 대상 |
|---|---|
| `PATCH /api/devices/{id}/crop` | `PATCH /api/pots/{대표 potId}/crop` |
| `GET /api/devices/{id}/measurements/latest` | 대표 화분의 최신 측정값 |
| `GET /api/devices/{id}/measurements` | 대표 화분의 시계열 |
| `GET /api/devices/{id}/score` | 대표 화분의 점수 |

컨트롤러 메서드 4개짜리 비용으로 프론트엔드 8개 화면을 지금 건드리지 않아도 된다.
프론트 전환은 todolist P2-6(mock 데이터 제거)과 묶어 한 번에 처리한다.

### 7.3 변경되는 동작

**`POST /api/devices`** — 계정당 N대 허용.

- `USER_ALREADY_HAS_DEVICE` 충돌 제거
- 요청 본문에 `spaceId`(선택) 추가: 있으면 기존 공간에 편입, 없으면 기존 `spaceName`/`spaceType`/
  `areaSquareMeters`로 새 공간 생성 — **기존 요청 형식은 그대로 동작한다**
- `serialCode` 필드는 이름을 유지하되 `device.claim_code`와 대조한다
- 성공 시 `pot` 1개 자동 생성

**`GET /api/me`** — 응답 형태 유지, 계산만 변경.

- `hasDevice` = 사용자에게 claim된 `device`가 1개 이상
- `hasCrop` = 사용자의 `pot` 중 `crop_code`가 있는 것이 1개 이상
- `device` 필드는 대표 게이트웨이 1개를 계속 반환 (프론트 `RootShell` 상태 머신 호환)

**`EnvironmentScoreService.latest`** — `deviceId` 대신 `potId`를 받고, 작물을 `pot.crop_code`에서
읽는다. `EnvironmentScoreResponse.deviceId`는 `potId`로 교체하되 JSON 필드명은 별칭 기간 동안
유지 여부를 구현 시 결정한다.

## 8. 엣지·펌웨어 변경

### 8.1 `edge/pi`

- `Publisher` 프로토콜 추출 (`send(Event) -> DeliveryResult`)
- `MqttPublisher` 구현 (paho-mqtt), 기존 `BackendClient`는 `HttpPublisher`로 개명·유지
- `Event.backend_body()`를 envelope v2 생성으로 교체 (게이트웨이 1건 + 노드 배열)
- `config.py`에 `TB_MQTT_HOST`, `TB_MQTT_PORT`, `TB_MQTT_USERNAME`, `TB_MQTT_PASSWORD`,
  `TB_MQTT_TLS`, `TB_MQTT_TOPIC_PREFIX` 추가
- `DeliveryResult` 판정을 HTTP status → 발행 결과/PUBACK 기준으로 재작성
- LWT 등록 및 접속 시 status retain 발행
- SQLite outbox는 **변경 없음**

### 8.2 `edge/arduino`

- PPFD 보정 활성화 (`TB_GY30_PPFD_CALIBRATION_ENABLED`)
- DS18B20 토양온도, 정전용량 토양수분 기본 활성화
- `soil_moisture_raw_adc` 필드 emit 추가
- `TB_NODE_ID` 프로비저닝 절차 문서화 (기본값 `UNCONFIGURED`)
